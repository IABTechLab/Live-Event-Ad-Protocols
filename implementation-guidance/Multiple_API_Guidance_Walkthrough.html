One live event, two APIs: from forecast to live concurrency

Follow a single championship broadcast from 30 days out to the moment its stream closes. Before the stream opens, the Forecast API is the plan. Once the stream opens, the Concurrent Streams API is the authoritative signal. Both carry the same content.id, so each snapshot lines up with the forecast and with the OpenRTB bid requests for the same event. Each call has three views: when it is made, what comes back, and what changed since the previous call. All values are made-up examples.
